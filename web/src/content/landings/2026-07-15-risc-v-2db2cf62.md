primer_expert: On RISC-V, stack ties are used in epilogues to mark stack frame changes
  for unwinders. When a frame pointer (`s0`) is not used, the original pattern for
  `stack_tie` incorrectly referenced `s0`, causing it to be considered live by later
  passes like `regrename`. This could lead to `s0` being modified when it should have
  been preserved as callee-saved. The fix introduces a dedicated `stack_tie_sp` pattern
  for epilogue barriers that only uses the stack pointer (`sp`), ensuring correctness
  regardless of frame pointer usage and preventing unwind corruption.

This commit addresses an issue in the RISC-V backend where epilogue stack ties incorrectly referenced the frame pointer (`s0`) when no frame pointer was used. This made the register appear live, potentially leading to `regrename` corrupting callee-saved state during exception unwinding. The fix introduces a new SP-only pattern for epilogue barriers, ensuring stack ties correctly reference only the stack pointer when a frame pointer is absent, thus preserving unwinding integrity.
