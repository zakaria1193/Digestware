This commit addresses a regression in the aarch64 backend where a specific pattern involving `(plus (and x MASK) IMM)` was not being correctly recognized as a single `MOVK` instruction. This was due to the cost model (`aarch64_rtx_costs`) charging a separate cost for an immediate move. The fix introduces `aarch64_movk_plus_p` to identify this pattern and cost it as a single logical instruction, resolving a test case failure and improving code generation efficiency.
