The `mode_unit_size` array, generated by `emit_mode_unit_size_inline`, previously used `unsigned char` by default. This is insufficient for architectures like `rs6000`, which can have opaque modes with sizes up to 256 bytes, causing an overflow. This change introduces a `MODE_UNIT_SIZE_TYPE` macro that dynamically selects `unsigned char`, `unsigned short`, or `unsigned int` based on the maximum size encountered in the `mode_unit_size` array, resolving the overflow issue.
