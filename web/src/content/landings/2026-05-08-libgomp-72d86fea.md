This commit inlines the `gomp_barrier_state_is_incremented` function within libgomp's busy-wait loops to address a flaw in handling generation wraparound combined with state flags. The original function could incorrectly report a generation increment when flags were present and wraparound occurred, causing a generation number decrease. The inlined version explicitly checks for a one-increment-ahead state, naturally handling overflow and avoiding unnecessary checks. This improves the robustness of barrier synchronization.
