primer_general: Compilers like GCC translate your code into an intermediate representation
  (IR) before generating machine code. One of these intermediate representations is
  called Static Single Assignment (SSA) form, which helps in various optimizations.
  When creating SSA, `PHI` nodes are introduced to merge values from different control
  flow paths. The `phiopt` pass then tries to optimize these `PHI` nodes. This commit
  refactors how the compiler looks for redundant computations (called "factoring")
  and redundant expressions (called "common subexpression elimination" or CSE) around
  these `PHI` nodes. By making these processes more integrated and iterative, the
  compiler can potentially find more opportunities to remove unnecessary load and
  store operations, making the compiled code faster and smaller. This is a subtle
  but important change in how GCC optimizes your programs, laying groundwork for future
  performance improvements.

This change in GCC's phiopt pass reorganizes factoring and common subexpression elimination (CSE) to improve optimizations. By moving the CSE loop into the factoring operation, all three factoring cases are now considered if any single case results in a change. This improved iteration prepares the ground for more effective load and store eliminations during optimization.
