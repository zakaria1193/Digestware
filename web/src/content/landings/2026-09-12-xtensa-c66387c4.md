The `xtensa_valid_move` function has been simplified by removing a workaround that prevented non-register sources from being directly assigned to the stack pointer. This check was originally necessary because the older Reload pass was less strict with operand constraints. With the adoption of the Later Register Allocator (LRA), which adheres strictly to constraints, this workaround is no longer needed, and the function can be safely simplified. A new test case ensures the correct behavior.
