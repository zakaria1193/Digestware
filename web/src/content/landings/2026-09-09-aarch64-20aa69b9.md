This change prevents floating-point intrinsics, like `vadd_f32`, from being optimized away when the `-ftrapping-math` option is used. Previously, if the result of such an intrinsic was unused, the instruction would be removed, which is problematic if it could generate a floating-point exception from a signalling NaN. A new function `build_optimization_barrier` is introduced to insert an `asm volatile` statement, creating a dependency on the result and preventing its dead code elimination.
