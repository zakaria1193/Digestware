This commit modifies the Xtensa backend to prefer general-purpose registers (GPRs) over hardware floating-point registers (FPRs) for single-precision floating-point (SFmode) load and store operations. While functionally equivalent, using GPRs results in smaller code size when the Code Density Option is enabled. This is achieved by prefixing the hardware FP register constraints in the MD insn definition with an asterisk ('*'), signaling a lower priority. The change is demonstrated with an example showing reduced instruction encoding length for loads, stores, and immediate assignments.
