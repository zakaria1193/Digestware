The ifcvt (if-conversion) pass has been improved to handle conditional diamond conversions, particularly on ARM, when the two branches of the diamond update different sets of live-out variables. Previously, it required overlapping live-outs, forcing the use of temporary variables for values only defined in one arm. This change allows for more flexible and efficient conversion by correctly managing disjoint live-outs and enabling one-set arms, improving code generation for conditional constructs.
