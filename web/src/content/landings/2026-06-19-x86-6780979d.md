primer_general: When writing programs, developers often use an `assembler` (like `gas`
  from Binutils) to translate human-readable assembly language into machine code that
  a computer's processor can execute. This machine code needs to be as efficient as
  possible. An `XADD` instruction on x86 processors means "exchange and add" — it
  atomcially exchanges a value in memory or a register with another value, then adds
  them. However, if you tell `XADD` to exchange and add a register with itself (e.g.,
  `xadd %eax, %eax`), it's functionally the same as just adding the register to itself
  (e.g., `add %eax, %eax`). This update to Binutils' `gas` now recognizes this specific
  scenario. Under optimization, when it sees `xadd %rN, %rN`, it will automatically
  replace it with the `add %rN, %rN` instruction. The `add` instruction is simpler,
  takes fewer internal processor resources, and has a shorter machine code representation,
  making the resulting program slightly faster and smaller.

The x86 backend of Binutils' GNU Assembler (GAS) now performs an optimization for `XADD` (exchange and add) instructions where both source and destination operands are the same register. In such cases, `xadd %rN, %rN` will be transformed into `add %rN, %rN` under optimization. This change improves execution resource usage and results in a shorter instruction encoding, leading to more efficient generated code.
