This change ensures that aggregate subobjects destroyed using `std::destroy_at` are correctly marked as outside their lifetime during constant evaluation. Previously, only a normal CONSTRUCTOR was recorded, leading to incorrect `std::is_within_lifetime` checks. By using `void_node` for these cases, similar to scalar subobjects, the compiler now accurately reflects the object's state, preventing potential runtime errors. The fix is applied to aggregate types but excludes `CLOBBER_OBJECT_START` and `CLOBBER_STORAGE_START` to avoid breaking existing functionality.
