This commit addresses a double-free bug in GCC's Fortran compiler (gfortran) that occurred during assignments where the right-hand side was a function call that redefined the left-hand side (LHS). If the LHS had allocatable components, gfortran would save and then free them after the assignment. If the function call modified the LHS, it could free already-freed components, leading to a double free, and leak the components remaining in the LHS. The fix evaluates the function call before saving the LHS components, resolving the issue.
