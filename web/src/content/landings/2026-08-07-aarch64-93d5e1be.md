  where `vec_extract`/`vec_set` idioms for two-element vector lane copies were folded
  into `VEC_PERM_EXPR`. The constant permute expander's patterns incorrectly tied

  address this by providing alternatives that tie the destination to the correct input,
  thus avoiding the extra move.

This commit resolves a performance regression on AArch64 where copying lanes in two-element vectors resulted in an extra register move instruction. By adding new patterns that correctly tie the destination register to the appropriate input, the compiler now generates more efficient code, reducing instructions from two to one for these operations.
