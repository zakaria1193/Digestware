The alias analysis in GCC previously failed to recognize when a pointer might alias the `errno` variable if the pointer's points-to set only contained named global variables (like `errno` itself). This led to incorrect optimizations where reads of `errno` across function calls were dropped, causing programs to see an unchanged `errno` value. This change updates the analysis to consider pointers aliasing named, interposable global variables as potential `errno` accesses.
