This commit corrects an issue in GCC where the address of a nested function was sometimes passed without generating a necessary trampoline. The bug occurred because the `mark_decl_used` function would incorrectly return early if a function was already marked, failing to propagate the marking to its parent functions. This prevented the generation of trampolines required for non-local context access. The fix ensures that parent functions are correctly marked, even if already processed, thus guaranteeing the generation of trampolines when a nested function requires a non-local context.
