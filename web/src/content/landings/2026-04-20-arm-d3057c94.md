The compiler now correctly generates code for half-precision floating-point moves (``mov<mode>_vfp_<mode>16``) on ARM devices that only support FP16 (and not Neon). The fix ensures that ``VLD1/VST1`` instructions are used only when address write-back is needed and ``NEON_FP16INST`` is available. Otherwise, ``VLDR/VSTR`` instructions are used, guaranteeing assembly on targets lacking Advanced SIMD.  A new test case and architecture variant were added to validate the fix, which prevents crashes on certain ARM platforms.
