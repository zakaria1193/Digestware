The GCC vectorizer can sometimes widen operands to match the result type, improving instruction efficiency. Previously, this widening was blocked if a loop-invariant operand had a range that didn't fit within the result's type, even if the operand's actual range was much narrower. This change modifies the vectorizer to query the precise range of loop-invariant operands and use the narrowest type that can hold that range. This allows widening to occur more often, as seen in an x265 optimization that reduced instruction count.
