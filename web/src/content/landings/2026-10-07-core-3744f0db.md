An optimization in `match.pd` has been corrected to prevent the introduction of signed integer overflow. The simplification `x != CST1 ? x + CST2 : CST3 -> x + CST2` could previously create overflow scenarios. The fix now checks if `CST1 + CST2` overflows; if it does and the type does not wrap around, the simplification is rewritten using unsigned addition to maintain correctness.
