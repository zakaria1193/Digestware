The AVR code generation for function prologues has been refined to be more efficient for small stack frames. The `prologue_saves` mechanism is now only invoked when its generated code sequence is shorter than an alternative using `RCALL` and `PUSH` instructions. This optimization avoids generating unnecessarily verbose prologue code for simple function entry sequences.
