The GCC vectorizer has been enhanced to elide unnecessary load permutations when dealing with strided grouped loads. Previously, a permutation selecting a consecutive run of lanes within a group was not always optimized, leading to less efficient scalar loads. This commit removes a restrictive requirement that the run length must divide the group size, allowing the vectorizer to treat such consecutive runs as a single group. This optimization significantly improves performance for patterns like half-pel motion estimation, reducing instruction count and improving vectorization efficiency on architectures like aarch64.
