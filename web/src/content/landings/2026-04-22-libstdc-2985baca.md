The `noexcept` specification of `indirect::operator==` didn't account for heterogeneous comparison with type `T` involving a boolean conversion, as per the standard draft (LWG4325).  The patch adjusts the `noexcept` specification to include this case, ensuring that the exception specification is correct, which is important for code that relies on `noexcept` for optimization or exception safety guarantees.
