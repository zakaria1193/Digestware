The gccrs compiler has been optimized to only add the specifically requested auto trait when probing for traits. Previously, the `TypeBoundsProbe::scan` function incorrectly added all auto traits to every probe. This led to redundant checks, causing exponential increases in type-checking time and memory usage, particularly with nested data structures, and preventing `libcore` from type-checking. This change resolves an issue where checking a trait on a nested struct would re-probe fields excessively.
