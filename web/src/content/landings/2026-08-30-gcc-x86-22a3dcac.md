primer_expert: On Darwin x86_64, the dynamic linker's lazy symbol resolution mechanism
  involves a stub routine that clobbers `d10` and `d11`. This behavior is in conflict
  with the `no_caller_saved_registers` function attribute, which signifies that a
  function must not modify any caller-saved registers. The `ix86_expand_call` function
  in `i386-expand.cc` now queries this attribute and overrides the stub's register
  reservation if the attribute is set. This check is performed on a hot path but testing
  showed no significant compile-time overhead.

- term: Lazy symbol resolution

    that use many dynamic libraries but call only a few functions from each.

On Darwin x86_64 systems prior to Darwin21, lazy symbol resolution uses a stub that overwrites registers d10 and d11. This commit ensures that if a function is explicitly marked with `no_caller_saved_registers`, this attribute takes precedence over the stub's register clobbering. This prevents unexpected register corruption when users specify this function attribute.
