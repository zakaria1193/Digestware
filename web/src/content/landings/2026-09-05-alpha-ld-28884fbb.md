primer_expert: In static linking on Alpha, taking the address of an IFUNC located
  in a read-only section is disallowed. This is because the `R_ALPHA_IRELATIVE` relocation,
  which is required to update the IFUNC address, needs to modify the target word.
  At runtime, the kernel maps segments as read-only. While the dynamic linker can
  later make these segments writable (DT_TEXTREL), a static executable cannot. Since
  Alpha does not have a PLT entry for non-dynamic functions, it cannot provide a PLT
  stub address as a fallback. This commit adds a check in `bfd/elf64-alpha.c` to detect
  and reject this scenario.

This commit modifies the Alpha linker to reject attempts to take an IFUNC address from read-only data in static executables. Unlike dynamic linking where segments can be made writable, static executables mapped by the kernel cannot have their read-only segments modified at runtime. Other targets typically provide a PLT stub address in such cases, but Alpha lacks a PLT entry for non-dynamic functions, leading to an error report instead.
