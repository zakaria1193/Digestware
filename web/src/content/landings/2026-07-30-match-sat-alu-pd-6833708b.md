GCC's `match-sat-alu.pd` pattern matcher now recognizes unsigned saturating additions where the clamping condition uses a strict inequality (`< MAX` instead of `<= MAX`). This strict form is equivalent to clamping at `MAX - 1` and is now correctly handled, enabling more efficient code generation. An AArch64 example shows a simplification from multiple instructions to a single `csinv` with a condition code.
