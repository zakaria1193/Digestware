primer_general: When GCC compiles your code, it performs various analyses to make
  your program run faster. One of these is called Interprocedural Analysis (IPA),
  which looks at how different functions interact. A key part of IPA is tracking the
  possible range of values a variable can have at different points in the program.
  This information, called a 'prange', helps GCC optimize. Sometimes, these ranges
  might contain 'invariants,' which are properties that always hold true. This update
  fixes a bug where GCC might incorrectly record return value ranges that included
  invariants tied to temporary, local variables within a function. If GCC tried to
  use this incorrect information, it could accidentally let one function see the memory
  address of a variable that only exists inside another function, potentially causing
  crashes or incorrect behavior. The change makes sure GCC only records "safe" invariants
  that can be correctly shared between functions.

GCC's Interprocedural Analysis (IPA) was updated to prevent recording return value ranges for "pranges" that contain non-IPA invariants. This change addresses a potential issue where the address of a local variable could be incorrectly propagated from one function to another, leading to incorrect program behavior. The `ipa_record_return_value_range_1` function now explicitly filters out such pranges.
