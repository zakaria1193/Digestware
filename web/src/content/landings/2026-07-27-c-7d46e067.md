primer_expert: GCC's C++ parser opens a lambda mangling scope when encountering a
  class head. If `begin_class_definition` subsequently rejects the class (e.g., due
  to a syntax error), it replaces the class head with `error_mark_node`. Previously,
  the scope cleanup logic did not account for this rejection, leaving the lambda scope
  incorrectly active. This change introduces a flag to track the opening of a lambda
  scope specifically for a class head, ensuring that the scope is properly closed
  even when the class definition fails.

When a class definition fails parsing in GCC's C++ front-end, the lambda scope cleanup was not correctly handled, leading to incorrect active scope information. This commit modifies the parser to track whether a lambda scope was opened for a class head, ensuring proper cleanup regardless of the class definition's success. This fixes PR125343.
