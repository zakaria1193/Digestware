This commit fixes an issue in GCC's middle-end CRC pass where loops with exactly 24 iterations were producing incorrect results. The CRC pass incorrectly created a 24-bit data type and derived the processing size from its mode, leading it to process 4 bytes instead of the intended 3. The fix modifies the CRC table expanders to use a passed bit size instead of inferring it from the mode, ensuring correct computation.
