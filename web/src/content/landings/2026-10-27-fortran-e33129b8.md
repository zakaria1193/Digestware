The Fortran compiler's type inference for `ASSOCIATE` constructs has been made target-independent to resolve cross-compilation failures. Previously, when an `ASSOCIATE` selector was a function not yet parsed, the compiler guessed the associate name's type based on the first component reference. This guess depended on the order symbols were inserted, which varied by target. The fix ensures the type guess is predictable by picking the first candidate type where the entire component chain exists and by collecting candidates using an in-order symbol tree walk. This change also improves handling of substring and array section parsing when the guessed component is a character array.
