GCC previously claimed support for Clang's modules, a feature tightly coupled with Clang's internal AST and not compatible with GCC's architecture. This misrepresentation caused build failures on macOS by affecting header declaration ordering. By removing this claim, GCC aims for parity with builds that do not use the -fmodules flag, aligning with the C++20 modules standard which uses a different feature test macro.
