A performance regression on the xstormy16 port has been fixed by reintroducing efficient arithmetic operation (aop) patterns. The aggressive use of aop previously led to less efficient code generation compared to the older IOR (integer operation) patterns. New expanders for QI (8-bit) and HI (16-bit) modes now steer aop towards IOR, resolving the performance issue.
