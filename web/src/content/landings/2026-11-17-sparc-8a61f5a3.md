A workaround for a SPARC erratum (GR712RC) has been improved to correctly handle cases where a floating-point operation follows an integer branch. Previously, if the epilogue started immediately at the branch target and contained zero-length frame blockages, the compiler might not insert a necessary NOP before the floating-point instruction. This commit modifies the `sparc_do_work_around_errata` function to use `next_active_non_empty_insn()` to find the true instruction at the branch target, ensuring correct instruction sequencing and fixing issues seen in `ceilf()` and `floorf()`.
