The `cond_store_replacement_limited` function incorrectly treated clobber operations as stores. This led to erroneous usage of `{CLOBBER(eos)}` as a phi argument, causing incorrect code generation. This change corrects the function to properly identify and reject clobbers, ensuring they are not mistaken for stores.
