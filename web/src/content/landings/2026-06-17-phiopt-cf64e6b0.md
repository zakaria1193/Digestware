primer_general: When GCC compiles your code, it tries to make it as efficient as possible.
  One technique is called "phi-optimization," which helps simplify how the program
  handles values that depend on conditional statements (like `if-else` blocks). Specifically,
  if a program loads data from memory in both branches of an `if` statement, this
  optimization tries to move that load operation to *before* the `if` statement, so
  it only happens once. Before this change, this particular optimization could only
  do this if the memory access was directly at the starting address of a variable.
  This update teaches the optimizer to also handle cases where the memory access is
  slightly offset from the start of a variable (e.g., accessing an element within
  an array). This leads to even more efficient compiled code by reducing redundant
  memory reads in certain situations, and fixes a bug where the compiler wasn't handling
  these offset loads correctly.

The GCC phi-optimization pass was enhanced to support non-zero offsets when factoring out conditional loads. Previously, the `factor_out_conditional_load` function only handled loads with zero offsets, which limited its optimization capabilities and led to incorrect code generation in certain scenarios. With this update, GCC can now optimize more complex load patterns, generating more efficient code and resolving a reported bug where such loads were not properly handled.
