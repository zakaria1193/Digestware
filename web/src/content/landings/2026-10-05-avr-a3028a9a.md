A bug in AVR code generation has been fixed where functions marked as `noreturn` and compiled with `-mcall-prologues`, which also receive arguments on the stack, produced incorrect code. The `prologue_saves` mechanism was saving more registers than necessary, leading to an incorrect argument pointer. The fix ensures that `prologue_saves` is not used in these specific scenarios by modifying `sequent_regs_live` to return zero for noreturn functions, thus preventing the erroneous register saving.
