This commit fixes a bug in GCC's loop unrolling optimization where the epilogue loop's iteration bound was incorrectly calculated when the loop's control variable wraps. Previously, the unroller assumed the main loop consumed all but fewer than `FACTOR` iterations. However, when the control IV wraps, this assumption breaks, leading to miscompilation. The fix ensures the epilogue bound is only set when the exit test is not a `NE_EXPR` or when the control IV is known not to wrap, otherwise inheriting the original loop's bound.
