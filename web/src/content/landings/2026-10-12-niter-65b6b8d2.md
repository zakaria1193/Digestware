This commit fixes an issue in GCC's loop iteration analysis for bit counting operations (`popcount`, `cltz`, `cltz_complement`). Previously, the analysis incorrectly assumed that the loop's exit condition always tested the same induction variable (IV) that was being modified within the loop. This could lead to incorrect iteration counts and miscompilation, as demonstrated with an example where the loop body modified one IV while the exit condition checked another. The fix ensures that the analysis validates that the exit test operates on the loop's recurrence PHI, improving correctness.
