This commit adjusts the `unsigned_integer_narrow_clip` pattern in GCC's matcher to reject cases where the operand is known to be the minimum value of its type. The original pattern could incorrectly rewrite a program when the minimum value was present, leading to a stored value of `NT_MAX` instead of the expected `0` on certain targets. The updated pattern now requires the minimum value not to occur, preserving correctness and resolving PR126981.
