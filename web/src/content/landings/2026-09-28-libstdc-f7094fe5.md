On systems lacking `unlinkat` or `dirent::d_type`, `libstdc++`'s directory traversal could fail to correctly identify file types. When `__erase` was called for a non-empty directory, it would use `::remove` which retries as `rmdir`. If `rmdir` failed due to the directory not being empty, the error was not handled correctly, leading `remove_all` to report a failure. This commit adjusts the error handling to accept `ENOTEMPTY` or `EEXIST` as valid failure reasons for `rmdir` in this specific scenario, allowing the operation to proceed.
