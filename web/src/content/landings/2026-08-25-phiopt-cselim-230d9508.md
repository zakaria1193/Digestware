The conditional store replacement pass (cond_store_replacement_limited) now supports constants for stores, extending its capabilities beyond just SSA names. This change allows the optimization to handle more cases, similar to the full cselim pass, by rejecting clobbers instead of restricting replacements to SSA names or specific invariants. This should enable better optimization for code involving constants in conditional stores.
