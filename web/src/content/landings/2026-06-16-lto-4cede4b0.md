GCC's Link-Time Optimization (LTO) has fixed an issue where the `loop->can_be_parallel` flag was not being streamed between compilation units. This meant that even if a frontend compiler marked a loop as suitable for parallelization using `annot_expr_parallel_kind`, the LTO stage would not receive this information, effectively disabling potential parallel optimizations. By streaming this flag in and out, LTO can now properly leverage frontend hints for parallel execution, potentially leading to better optimized code for parallelizable loops.
