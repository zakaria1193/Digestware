The `get_memory_rtx` function in `builtins.cc` previously created memory operands without distinguishing between loads and stores. This led to the loss of `MEM_NOTRAP` information for loads, as the default assumed store semantics. This commit adds a `STORE_P` argument to `get_memory_rtx`, allowing callers to explicitly mark destinations as stores and sources as loads. This preserves precise non-trapping information for loads used in string operations and comparisons.
