The GCC RISC-V backend now correctly handles `mode_idx` for widen-ALU operations (`viwalu`, `vfwalu`, `viwmul`, `vfwmul`) when they are used in scalar contexts during vectorization. Previously, the system would query a scalar source operand instead of a vector operand, leading to an incorrect Available Vector Length (AVL) calculation within `avlprop`. By moving these operations to the correct bucket with `mode_idx` set to 3, the vector length propagation is now accurate, ensuring proper vector instruction generation for widening operations.
