This commit addresses a bootstrap failure in the sccvn (Strongly Connected Components Value Numbering) pass by correctly handling executable dominators. A previous change introduced a global table, `vn_exec_idom`, which needs to be managed by the `vn_driver::finalize` method. The driver now owns this table, ensuring it is available and correctly pointed to during the finalization process, which also involves updating `vn_bb_to_rpo`. This keeps the value numbers consistent between the walk and finalize stages.
