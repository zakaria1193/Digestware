This commit addresses a mis-compilation issue on RISC-V targets related to bit manipulation instructions. The problem occurred when a `define_split` pattern was used on a register where bits beyond the lower 32 were non-zero, leading to incorrect code generation. By conditioning the split on `nonzero_bits`, the compiler now uses the optimized pattern only when appropriate, and falls back to a correct, albeit potentially less optimized, sequence otherwise. A new test case specifically triggers this bug.
