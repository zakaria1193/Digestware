primer_expert: The `exploded_graph::get_or_create_node` function previously performed
  multiple deep copies of `program_state` when creating a new `exploded_node`. This
  was inefficient as `program_state` owned its `region_model` and `sm_state_map` via
  pointers, leading to redundant cloning. This patch introduces move assignment for
  `program_state` and move constructors/overloads for `point_and_state` and `exploded_node`,
  changing the creation cost from three deep copies to one move operation. A copy
  of `pruned_state` is retained for use as a stable hash map key during merge operations.

GCC's static analyzer now avoids deep-copying `program_state` when creating new `exploded_node`s. By introducing move support for `program_state`, `point_and_state`, and `exploded_node`, the process of creating a new node is reduced from three deep copies to a single move operation, significantly improving performance.
