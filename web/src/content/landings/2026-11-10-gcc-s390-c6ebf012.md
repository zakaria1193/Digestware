Since GCC 4.6, s390 passed nullptr_t arguments in registers but returned nullptr_t values through memory, which contradicts the psABI. The fix teaches s390_return_in_memory to treat NULLPTR_TYPE like other register-passed scalars, as s390_function_arg_integer already does. A memory return adds a hidden first argument, so this change shifts every named argument of affected functions by one GPR. Code built with GCC 17 that calls a nullptr_t-returning function compiled with an older GCC (or the reverse) can therefore crash. A new psABI note warns about the change, and it skips functions that have no external linkage and whose address is never taken.
