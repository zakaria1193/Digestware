primer_glossary:
- term: auto-trait
  definition: A special kind of trait in Rust (e.g., `Send`, `Sync`, `Copy`) whose
    implementation is automatically inferred by the compiler based on the structure
    of a type. For example, a struct is `Send` if all of its fields are `Send`.
- term: trait bound
  definition: 'A constraint on a generic type parameter, specifying that the type
    must implement a certain trait. For example, `<T: Display>` means `T` must implement
    the `Display` trait.'
- term: negative impl
  definition: A Rust construct that explicitly states a type does *not* implement
    a certain trait. This is typically used in sophisticated trait implementations
    or coherence rules to prevent certain types from satisfying specific bounds.
- term: struct
  definition: A composite data type in Rust that groups together fields (variables)
    under a single name. Structs are used to create custom data structures.
- term: field propagation
  definition: The process where properties or characteristics of a larger structure
    (like auto-trait status) are determined by examining the properties of its individual
    components (fields).

This commit enhances gccrs's type-checking capabilities by introducing support for propagating auto-trait information through struct fields. It also refines the handling of negative trait implementations, ensuring that a type does not satisfy a bound if a negative implementation exists for it. These changes improve the compiler's accuracy in verifying type constraints and trait bounds.
