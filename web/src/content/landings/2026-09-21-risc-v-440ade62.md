This change corrects how callee-saved floating-point registers (FPRs) are saved on the stack when using the RISC-V Zcmp extension and optimizing for size (-Os). Previously, the prologue could incorrectly calculate the space needed for these registers, leading to them being stored below the stack pointer without sufficient allocation. This could cause an interrupt to overwrite these registers before they were properly saved, corrupting program state. The fix ensures that only as many FPRs are folded into the `cm.push` reserve as can be physically stored.
