primer_general: When you compile a program using GCC, the compiler itself requires
  a certain amount of memory to do its work, including a dedicated area called the
  "stack." This stack stores temporary data and information about currently active
  functions. This commit addresses a problem where, if GCC itself was compiled with
  a special debugging tool called AddressSanitizer (ASAN), it would sometimes run
  out of stack space when trying to compile very complex C test cases. ASAN is a tool
  that helps detect memory errors in programs by adding extra checks, which in turn
  increases the compiler's own memory usage. To prevent these internal compiler crashes,
  GCC will now ask for twice the amount of stack space (128 megabytes instead of 64
  megabytes) when it detects that it was built with ASAN enabled. This change helps
  ensure the compiler remains stable and functional even when using powerful debugging
  tools on its own codebase.

This commit addresses a stack overflow issue encountered when running specific test cases with a GCC compiler that has been instrumented with AddressSanitizer (ASAN). The previous 64MB stack limit proved insufficient for `gcc.c-torture/compile/limits-exprparen.c`. To resolve this, the compiler will now request a larger 128MB stack if it was itself built with ASAN, preventing crashes during its own compilation processes.
