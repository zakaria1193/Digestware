A RISC-V optimization pass, `combine_popretz`, incorrectly deleted a `li a0, 0` instruction when it occurred across a function call. This instruction was intended to set up the first argument for the called function or to clear register `a0` before a return. The pass's backward scan failed to stop at calls, mistaking argument setup for dead code. This commit corrects the scan to respect function call boundaries, preventing incorrect instruction deletion and ensuring correct argument passing and return values.
