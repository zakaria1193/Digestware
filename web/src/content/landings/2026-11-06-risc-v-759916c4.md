primer_glossary:
- term: RISC-V
  definition: An open-standard instruction set architecture (ISA) based on Reduced
    Instruction Set Computer principles. GCC supports various RISC-V profiles and
    extensions.
- term: vector extension
  definition: A set of instructions that operate on multiple data elements in parallel,
    often used for high-performance computing and signal processing. GCC's support
    for vector extensions allows for SIMD (Single Instruction, Multiple Data) operations.
- term: SEW
  definition: Standard Element Width. In the RISC-V vector extension, this defines
    the width of individual elements within a vector register.
- term: EEW
  definition: Effective Element Width. This is the actual width of elements processed
    by a vector instruction, which can be different from SEW due to widening or narrowing
    operations.
- term: register group
  definition: A logical grouping of vector registers on the RISC-V architecture, often
    defined by the vector extension specification. Certain instructions or operand
    types may have constraints on which register groups they can use to avoid conflicts
    or ensure proper operation.
- term: vs1
  definition: The first source vector register operand for a RISC-V vector instruction.
- term: vs2
  definition: The second source vector register operand for a RISC-V vector instruction.
- term: vd
  definition: The destination vector register for a RISC-V vector instruction.
- term: Wn4 constraint
  definition: A constraint in RISC-V vector assembly that specifies a requirement
    for a register, often related to its EEW or its alignment within a larger register
    group. 'Wn4' likely refers to a constraint on a register that is 4 elements wide.

Several commits add new test cases to the RISC-V test suite. These tests focus on the `vwadd.wv` and `vwaddu.wv` vector instructions, specifically ensuring that the source register `vs1` does not improperly overlap with the destination register `vd` or the other source register `vs2`. One commit adjusts existing test cases for `m4` configurations where register allocation changed due to high register pressure.
