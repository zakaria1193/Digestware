This commit corrects an issue on the RISC-V architecture where the `REG_CFA_DEF_CFA` debugging note was being attached to the wrong instruction. Specifically, the note, which defines the Call Frame Address (CFA), should be associated with the instruction that copies the stack pointer to a temporary register, but it was previously attached to the instruction preceding this copy.

This incorrect placement could lead to inaccurate stack unwinding information. The fix ensures the note is correctly associated with the stack pointer copy, improving the reliability of debugging information, although it does not affect code generation itself.
