A linker script such as OUTPUT_FORMAT("elf64-bpfle") can retarget the output BFD while the x86 emulation is still active. `bfd_elf_linker_x86_set_options` then takes the target id from the foreign backend. The id check in `elf_x86_hash_table` passed because the id and the hash table came from the same foreign backend. The x86 code then treated that table as `struct elf_x86_link_hash_table`. Writing `htab->params` overflowed the heap block, an 8-byte write 424 bytes past a 1848-byte allocation under AddressSanitizer. The fix checks the id after `is_elf_hash_table` and accepts only x86 ids. Non-ELF outputs such as "binary" still short-circuit before `bed->target_id` is read, because those formats have no ELF backend data and reading the id would segfault. New tests `arch-confusion.exp` and `arch-confusion.s` cover both cases (PR ld/34874).
