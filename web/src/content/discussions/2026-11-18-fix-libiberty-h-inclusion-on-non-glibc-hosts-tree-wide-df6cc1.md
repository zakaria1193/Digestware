  (like FreeBSD) that emerged after `memrchr` was added to `libiberty.h`. The core
  issue is that `libiberty.h` now relies on `memrchr`, which needs to be detected

This patch corrects an issue where `libiberty.h` inclusion fails on non-glibc hosts (like FreeBSD) after `memrchr` support was added in 2025. The fix involves adding an `AC_CHECK_FUNCS` for `memrchr` in various project configurations and ensuring `config.h` is included where necessary. The change is described as 'tad invasive' due to its widespread application but is deemed essential for cross-platform compatibility.
