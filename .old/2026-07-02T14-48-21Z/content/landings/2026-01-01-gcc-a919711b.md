primer_general: When you write a function inside another function in C (a 'nested
  function'), the inner function needs a way to access variables from its outer, enclosing
  function. This access is managed through something called a 'static chain,' which
  is essentially a pointer to the enclosing function's context. Traditionally, compilers
  like GCC might generate small helper functions called 'trampolines' to handle calls
  to these nested functions. These trampolines take up extra space and can sometimes
  prevent the compiler from performing advanced optimizations, such as making function
  calls more direct (devirtualization). This change provides new tools (built-in functions)
  that let the compiler directly access the nested function's code and its static
  chain. By giving the compiler these direct access methods, it can generate more
  efficient code that avoids the need for trampolines, leading to smaller and faster
  programs, especially in scenarios where nested functions are used.

This update introduces two new built-ins, `__builtin_call_code_address` and `__builtin_call_static_chain`, which allow developers to extract the code address and the static chain pointer from a nested function. These can be used in conjunction with `__builtin_call_with_static_chain` to call nested functions more efficiently. This feature helps avoid trampoline creation and can improve performance by enabling optimizations like devirtualization, which trampolines often hinder.
