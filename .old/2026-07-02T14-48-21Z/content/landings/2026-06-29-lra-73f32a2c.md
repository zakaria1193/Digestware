  solving for dependent operands, has been updated. Previously, if the reference operand

primer_general: Compilers often perform a phase called Liveness Range Analysis (LRA)
  to determine how long a variable needs to be stored in a register. This helps optimize
  register usage. When certain operations depend on the outcome of others, LRA uses
  'filters' to ensure correct register allocation. This change allows these filters
  to be more discerning. If the dependency isn't yet fully defined, the filter will
  now be explicitly told that the dependency is 'invalid'. This lets the compiler
  identify potential problems earlier, preventing it from allocating a register that
  might later prove unusable, thus avoiding costly backtracking or incorrect code
  generation.

The Liveness Range Analysis (LRA) pass now passes `INVALID_REGNUM` to dependent filters when the reference operand is not yet determined. This allows filters to reject invalid choices earlier in the process, preventing situations where a hard register is chosen and later found unsuitable, which was unrecoverable. The change also improves filtering by checking subregisters first.
