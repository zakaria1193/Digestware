primer_general: Compilers convert your high-level code into low-level machine instructions.
  For ARM's AArch64 architecture, there's a special set of instructions called Advanced
  SIMD (AdvSIMD) that can perform operations on multiple pieces of data at once, using
  dedicated vector registers. Inside the compiler, there's a phase called 'reload'
  where actual physical registers are assigned to the temporary ones used by the compiler.
  This commit fixes a bug where, under specific circumstances, moving a 'partial'
  AdvSIMD vector (meaning it doesn't fill the entire register) from one register to
  another would cause the compiler to fail during this reload phase. The problem was
  related to how the compiler estimated the 'cost' of this move, which prevented it
  from finding a correct way to split the instruction. The fix involves adding a new
  instruction pattern to correctly handle these specific vector movements, ensuring
  that the compiler can generate valid code without crashing.

This commit resolves an issue in GCC's AArch64 backend where direct register-to-register transfers of partial Advanced SIMD (AdvSIMD) vectors could fail during the reload phase. The problem arose when the transfer cost between register classes was exactly 2, preventing the Linear Scan Register Allocator (LRA) from trying alternative reload strategies. The fix adds a specific instruction alternative for these sub-64-bit vector movements, ensuring proper code generation.
