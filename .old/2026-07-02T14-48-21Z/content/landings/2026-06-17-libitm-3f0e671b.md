  language to achieve maximum performance or interact closely with hardware features.
  `libitm`, a library for transactional memory, includes such assembly code for ARM's
  AArch64 architecture. Modern AArch64 processors have security features like Branch
  Target Identification (BTI) and Pointer Authentication Codes (PAC) to prevent malicious
  code from executing. It's important for compiled programs to clearly signal whether
  they use or are compatible with these security features. This update changes `libitm`'s
  assembly code so that it now uses a newer, more standardized way (called "AArch64
  build attributes") to communicate BTI and PAC support when the compiler and assembler
  understand this newer method. If they don't, it falls back to an older, compatible
  method ("GNU property notes"). This ensures programs built with `libitm` correctly
  declare their security capabilities across different toolchain versions.

This commit updates `libitm`'s hand-written AArch64 assembly to emit modern AArch64 build attributes for Branch Target Identification (BTI) and Pointer Authentication Codes (PAC). These attributes are used when the `__ARM_BUILDATTR64_FV` macro is available, indicating compiler and assembler support. For toolchains lacking this support, `libitm` falls back to emitting the traditional GNU property notes, ensuring backward compatibility while adopting modern security feature signaling.
