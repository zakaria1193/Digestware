primer_general: Compilers work by representing your code in an internal structure
  called an "abstract syntax tree" or "tree." When you declare an array, the compiler's
  internal representation might wrap the base type (like `int` or `char`) with an
  `ARRAY_TYPE` wrapper. Sometimes, when the compiler needs to understand the underlying
  type of a variable, it needs to "strip" away these array wrappers. This commit updates
  the GCC compiler, specifically for AVR microcontrollers (small, embedded processors),
  to use a standardized utility function called `strip_array_types`. Instead of each
  part of the AVR backend writing its own logic to remove these wrappers, they now
  all use this single, shared function. This makes the compiler's code cleaner, easier
  to maintain, and more reliable when dealing with array types in various contexts,
  such as when checking for program memory or inserting special attributes.

The GCC backend for AVR microcontrollers has been updated to utilize the `strip_array_types` function from `tree.h`. This change streamlines several functions within `avr.cc`, including `avr_progmem_p`, `avr_nonconst_pointer_addrspace`, `avr_insert_attributes`, and `avr_decl_maybe_lds_p`, which previously had custom logic to remove `ARRAY_TYPEs`. By using a shared utility, the code becomes cleaner and more maintainable.
