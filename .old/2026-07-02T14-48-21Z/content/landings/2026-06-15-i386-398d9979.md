  number using SSE instructions on an i386 processor, GCC converts these operations
  into a series of machine instructions. Sometimes, the compiler optimizes these instructions
  in a phase called `late-combine`. Before this change, if the program performed several

  loads, leading to slightly smaller code and potentially faster execution, especially
  when these operations are performed multiple times in a row.

GCC's i386 backend now better optimizes SSE floating-point absolute value and negation operations by assigning a nominal cost to memory loads within the instruction cost calculation. Previously, the `late-combine` pass would propagate sign-bit masks from the constant pool, often un-CSEing these loads because the `USE` of a memory operand had no associated cost in `ix86_insn_cost`. This led to inefficient code generation with redundant memory accesses. By introducing a cost for memory `USE`s, the compiler is now more likely to CSE these loads, reducing code size and improving overall performance for sequences of these operations.
