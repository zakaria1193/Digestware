primer_expert: This change modifies the `generic_cost` function in `x86-tune-costs.h`
  to increase `branch_mispredict_scale` from `COSTS_N_INSNS (2)` to `COSTS_N_INSNS

primer_general: Modern computer processors (CPUs) work like assembly lines, processing
  instructions in stages, which is called a pipeline. When your code has an 'if' statement,
  the CPU tries to guess which path the code will take (e.g., if the 'if' condition
  is true or false) to keep the pipeline full. If its guess is wrong, it's called
  a 'branch misprediction,' and the CPU has to throw away all the work it did based
  on the wrong guess and restart, causing a significant slowdown. This change tells
  GCC, the compiler, that these mispredictions are now even more expensive on newer
  x86 CPUs. Because of this, GCC will try harder to transform 'if' statements into
  sequences of instructions that don't involve unpredictable branches (a technique
  called 'if-conversion'), which helps your programs run faster and more smoothly
  on modern hardware by preventing these costly pipeline stalls.

GCC has increased the estimated cost of branch mispredictions for generic x86 tuning profiles. This change reflects the deeper pipelines in modern CPUs, where mispredicted branches incur a higher performance penalty. By making mispredictions appear more expensive, GCC's optimizer is more likely to employ 'if-conversion,' which transforms branching code into conditional moves, thereby reducing pipeline stalls and improving CPU utilization.
