primer_expert: On RISC-V, the `TARGET_SETJMP_PRESERVES_NONVOLATILE_REGS_P` macro in
  `riscv.cc` dictates whether `setjmp` and `longjmp` preserve callee-saved registers.
  Prior to this, the compiler assumed they did not, leading to incorrect stack frame
  handling across `setjmp`/`longjmp` boundaries given GLIBC's behavior. Explicitly

  non-local jumps.
primer_general: When a program calls a function, some data is stored in special memory
  locations called registers. Depending on the type of register, the calling function
  or the called function is responsible for saving its content. These are called caller-saved
  or callee-saved registers. The `setjmp` and `longjmp` functions in C are used for
  non-local jumps, allowing a program to jump out of a deeply nested function call
  and return to an earlier execution point, which is important for error handling.
  For the RISC-V architecture, the compiler wasn't correctly accounting for how `setjmp`
  interacts with these registers in the GLIBC standard library. This fix tells the
  compiler that `setjmp` saves the 'callee-saved' registers, ensuring that when the
  program jumps back with `longjmp`, the data in those registers is correctly restored,
  preventing crashes or unexpected program behavior.

This commit resolves a long-standing issue (PR87466) by explicitly defining `TARGET_SETJMP_PRESERVES_NONVOLATILE_REGS_P` for the RISC-V target. This informs the compiler that `setjmp` saves callee-saved registers as per the GLIBC implementation, allowing for more correct code generation and avoiding potential crashes or incorrect program behavior.
